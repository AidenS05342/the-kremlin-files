⏺ That's enough to work from. I don't have any essential design questions left.
  The only remaining decision is how to build it, and that should be a quick
  one.

  Three ways to build it

  A. Hand-built static site using plain HTML, CSS, and JavaScript (my 
  recommendation)
  The story lives in a data file listing scenes, documents, dialogue, and
  choices. A small engine I write tracks trust, flags, discovered documents, and
  act progression. The interface is a custom Soviet office "desktop" with a
  file tray, typewritten documents you open and stamp, a rotary phone, and a
  terminal.
  - Advantages: nothing to install, no build step, and it publishes to GitHub
    Pages as-is. You get full control over the look, which is your top priority.
    The story data is separate from the code, so you can write or edit branches
    without touching the engine.
  - Disadvantages: I write the branching engine myself, which is about half a
    day. There's no visual tool for mapping out branches, though I'd give you a
    script that checks every path leads somewhere.

  B. Twine (SugarCube) with heavy custom styling
  Twine is a popular tool in Digital Humanities for interactive fiction, and it
  gives you a visual map of passages.
  - Advantages: quick to write branching text, and your instructor may recognize
    it.
  - Disadvantages: Twine thinks in terms of "pages of text with links". A
    desktop interface with folders you open, a phone, and a separate file system
    would fight it the whole way. Most of the polish would be CSS hacks layered
    on top of it, which works against priority #1.

  C. A React or Vite app
  - Advantages: a clean component structure that would scale well beyond this
    project.
  - Disadvantages: it requires installing npm dependencies and setting up a
    build-and-deploy pipeline for GitHub Pages. That's real overhead in five
    days for little gain at this size, and the repository gets harder for a
    reviewer to read.

  I recommend A. It's the most direct path to a polished, distinctive interface.
  It needs zero dependencies, so there's nothing to ask your permission to
  install. And a reviewer can open the repository and see clean, readable files:
  the story data, the engine, the styles, and the About and bibliography pages.

  Which way do you want to go? Once you pick, I'll write the design document
  with the Monday prototype scope and the later work marked separately, and send
  it to you for approval.
